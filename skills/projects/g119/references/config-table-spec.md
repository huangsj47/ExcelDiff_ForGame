# G119 配置表规范（qz_config）

本文件是 **G119 项目**的配表事实来源：ID 怎么编、表怎么命名、哪些表属于哪个系统。
通用的「配表改动该查什么」在平台内置 skill 的 `incident-checklist.md` 里，不在这里。

## ID 规范

- 主要配置表的 `ID` 为 **6 位数**，例如 `101000`；部分数据量特别大的表可扩展到 7 位。
- 前两位是**类型段**，后 4 位由策划内部自行划分。
- ID 唯一性的主要好处是便于查找与定位：Debug 系统或外部 Log 系统可以直接按 ID
  反查配置数据。
- **但不是所有配置表都要求 ID 唯一。**
- 策划侧推行 **ID 段的占用规则**，尤其是海外版与国服之间——这条规则的存在本身
  就说明历史上出现过**两边各自取号导致 ID 冲突**的问题。

## 命名规范

支持三种命名方式，**建议采用第一种**，因为最明确：

```
【10】角色表_CfgRole.xlsx     ← 推荐：ID 分类 + Lua 文件名 + 具体描述
角色表_CfgRole.xlsx
CfgRole.xlsx
```

看文件名就能定位系统：`【NN】` 前缀是 ID 段位，`CfgXxx` 是生成的 Lua 模块名。

括号在仓库里实际用**全角** `【】`（`config/` 下带号段的表 69 个全是全角，半角一个都没有）。

## 表结构约定

- 一个 Excel 文件对应**一份**配置数据。尽量不要把几份配置数据写在一个 Excel 里
  （便于查找和对接）。
- 表尽量别太大，**能分表则分表**（减小热更关联和体积）。
- 字段名尽量短（减小配置文件大小）。
- **字段尽量少用 `custom` 类型**：custom 对策划不太友好，容易配错，且不方便检测。
  这是规范上的不推荐项，**本身不是缺陷**——评审时最多作为建议提出。
- 生成的配置表产物是 **`CfgXxx.lua`**，例如 `CfgModlue.lua`、`CfgModuleSub.lua`。
- 导表链路上还有一批工具脚本（批量导出、差异导出、导表工具、右键菜单等），
  它们自身的改动也属于「配置表变更」的范围。

## 表与产物要一起看（本项目事实）

- **一张表和它的产物是同一次导表产生的**：改了 `【30】道具表_CfgItem.xlsx`，`CfgItem.lua`
  必然跟着变。所以评审配表改动时，**表与其产物要当成一次改动来看**。
- 只看表或只看产物都看不出这类问题：**表里加了 ID、产物里没有对应项**（或反过来，
  产物里还留着表里已经删掉的条目、旧逻辑没跟着走）。每一侧单独看都是正常的。
- 注意本项目产物的两种形态：规范上是 `CfgXxx.lua`，线上改动里还常见
  `code/qz_pub/cfg/<模块名>CfgMod.lua`。后者的模块名（`BagAttrCfgMod` 之类）与中文表名
  **在名字上没有任何共同记号**，靠名字猜「RoleAttr 就是角色属性」是会猜错的 ——
  平台因此不硬配，改动清单里也就不会出现这层关联，**这层关系要靠你自己在本文件里
  写明的这条规矩去补**。

## 类型段

| 号段 | 类型 |
|---|---|
| `10`–`19` | 角色相关（含属性） |
| `20`–`29` | 场景、地图、关卡相关 |
| `30`–`39` | 道具相关 |
| `40`–`49` | 怪物相关 |
| `50`–`59` | 武器相关 |
| `60`–`69` | 技能相关 |
| `70`–`79` | 任务相关 |

## 表划分

| 系统 | 该段下已有的表 |
|---|---|
| 角色（10–19） | 角色等级、角色模型、角色属性、属性表、主角事件表 |
| 地图场景（20–29） | 场景表(20)、地图表(21)、传送点表(22)、贴花表、建筑材质表、动态阻挡表 |
| 道具（30–39） | 道具分类、道具增益、防具类型、道具效果表、通用消耗品表、道具-防具、道具-配件、道具-普通、道具-武器、道具-消耗品、物品合成表 |
| 怪物（40–49） | 怪物表、怪物事件表、重置行为树 |
| 武器（50–59） | 投掷物表、前后缀随机 |
| 技能（60–69） | 被动技能组合、AOE表、爆炸表、被动技能表、主动技能组合表、主动技能数值表、Buff表 |
| 任务（70–79） | 任务节点表、任务组 |
| 商店商城 | 商店表、商品表 |
| 数值相关 | —— |
| 其他系统 | 名字随机表、新手引导表、功能开启表、功能UI表现、中文表、书信内容表、通知提示表、制造台表、全局表、特效表 |

> **用法**：拿到改动路径或表名时，先按上表判断它属于哪个系统，再决定要回归的下游范围。
> 表名里的 `【NN】` 前缀、文件名里的 `CfgXxx`、以及 ID 的前两位都能用来定位。
