# 玩法语义与归因辅助

来源：项目的玩法辅助知识文档。它的用途是**玩法语义词典 + 归因护栏 + 职能路由**。

> 原文的使用边界：「这里提供玩法语义，**不替代**用户描述、录像、日志或实际配置。」
> 也就是说，**它不含工程结构信息**——没有引擎、语言、目录约定、模块划分，也没有
> 配置表字段结构（配置表请看 `config-table-spec.md`）。不要把它当成项目结构手册。

## 一局流程

| 阶段 | 内容 | 建单时重点记录 |
|---|---|---|
| 出生区域集结 | 单人或四人队进入副本并等待开门 | 队伍人数、是否有人未加载或掉队、开门或状态异常 |
| 野外接近或传送入场 | 玩家步行穿过野外，或从出生区域直接传送到地宫 | 入场方式、传送目标、区域或楼层判定、队伍是否同步 |
| 地宫探索 | 搜索房间、搜刮回收物、使用吸灵器、躲避或击杀怪物 | 地图或地宫或楼层或房间、交互对象、动作链、怪物干扰 |
| 返程撤离 | 达到价值目标后返回出生区域并结算，也可能死亡、超时或失败 | 撤离条件、队员状态、带出价值、失败原因、结算一致性 |

**阶段判定的硬规则（很重要，直接可用于风险推断）**：

> 固定集结等待、步行入场和传送入场是**不同阶段**。描述「首次交互慢」「总时长异常」
> 「进入地宫后无响应」时，**先确认问题发生在哪个阶段，不能直接归因于吸灵器或地宫逻辑**。

推论：改动「集结或开门」「步行入场」「传送落点」中的任意一处，都会让这三类问题的
归因互相污染，需要分别验证。

## 核心系统

| 系统 | 含义 |
|---|---|
| 搜打撤循环 | 探索移动、搜刮资源、战斗或躲避怪物、达到价值目标、返程撤离 |
| **吸灵器** | 地宫探索中的交互工具，可能参与吸取、喷出、拖拽、破坏、容器或 QTE 和拾取衔接，**不是脱离主循环的独立小游戏** |
| 四人协作 | 一人交互时，其他人可能继续探索、搜刮、战斗、掩护或等待 |
| Loot 与背包 | 地面掉落物可能通过拾取列表进入背包；满包时可能先丢弃低价值物再重新拾取。需要记录丢弃、回包、重拾和最终价值结果 |
| 怪物压力 | 吸灵器或搜刮窗口可能与受击、追杀、击杀、死亡、复活交错 |

> **改吸灵器的任一子行为，回归面是全链而不是单点**：上表 6 类交互链加上拾取衔接。

## 吸灵器交互链

每一行都是该物件**完整的验收路径**——改动涉及某类物件时，动作链的每一环都要走通。

| 类型 | 代表对象 | 需要描述的动作链 | 常见故障方向 |
|---|---|---|---|
| 持续吸取 | 土堆、挂画、小动物等 | 靠近或朝向 → 持续吸取 → 完成或奖励 → 恢复行动 | 瞄准不稳、中断、卡住、奖励或恢复延迟 |
| 直接吸收 | 书籍、报纸、纸箱、现金或硬币堆等 | 选中 → 吸入或飞入 → 消失或奖励 | 吸空、目标不消失、反馈延迟、连吸失败 |
| 两段式拖拽 | 窗帘、绳索木箱等 | 吸住 → 后退拉扯 → 二次操作 → 打开或破坏 | 第二段不出现、方向异常、输入锁死、终态错误 |
| 吸后喷出 | 零钱罐等 | 吸住 → 进入阻塞 → 喷出 → 击碎或掉落 | 喷出不可用、提前结束、击碎或奖励延迟 |
| 容器与 QTE | 衣柜、棺椁及容器物件 | 靠近 → 交互或 QTE → 等待掉落 → 拾取 | 距离、QTE、掉落、拾取或背包替换异常 |
| 散件 Loot | 地面掉落物 | 展示拾取列表 → 拾取；满包时丢弃再重拾 | UI 生命周期、丢弃回包、品质或价值或重拾结果错误 |

**同名美术物件可能因运行时组件不同走不同流程。** 没有实际配置、日志或复现证据时，
**不得仅凭物件名称断言技术实现或根因**。

## 反过度归因护栏

这五条是整个文档里**最该直接照着执行**的部分——它们就是分析时最容易犯的误判。
每条都是「不得直接解释为」：

- 操作次数更多 **不得** 直接解释为互动更丰富，可能是重复触发或失败重试。
- 单次时长更短 **不得** 直接解释为操作更顺手，可能是取消、截断或快速重开。
- 撤离结果相近 **不得** 直接排除吸灵器、地图、怪物或结算问题。
- 未发生交互 **不得** 直接解释为玩家拒绝，可能没有看到、没有进入范围或日志缺失。
- 缺少对象、阶段、完成、奖励或前后状态时，**不得**把通用现象写成具体物件根因。

## 描述完整性（同时是异常条目的写法要求）

一条合格的异常描述要能回答六件事。本 skill 的 `evidence` 与 `title` 按这个标准写：

- **阶段**：集结、入场、地宫探索、返程撤离或结算
- **模式与条件**：单人还是四人队、地图或地宫或楼层或房间、步行还是传送、首次还是重复、
  背包状态、怪物是否在场
- **对象与动作链**：交互对象是什么、执行到哪一步、哪一步没有进入预期终态
- **实际结果**：卡住、输入锁、状态不同步、无反馈、无奖励、数值错误、掉落或拾取失败
- **预期结果**：完成动作后系统应出现的、可验证的结果
- **影响范围**：是否阻断搜刮、战斗、队伍推进、撤离或结算

**标题规范**：优先用 `【系统或模块】对象或条件下的可观察异常`，
例如 `【吸灵器】窗帘拖拽完成第一段后未进入二次操作`。
**不要把未经证实的原因写进标题。**

## 需求侧应补齐的内容

如果需求或任务描述里缺下面这些，属于信息缺口，应当在报告里标注（不要自行编造）：

目标体验、影响阶段、玩家动作链、单人还是四人队差异、规则边界、异常或取消路径、
反馈与奖励、验收结果。

补充规则：**若描述只有「更快、更早、更多」，需要把它转换成可验证规则，
不能自动写成体验改善。**

版本字段规则：参考资料把 M4 作为体验参照、M5 作为扩展交互版本，这是**分析背景**，
不是当前工单的默认版本字段。用户未明确提及时，**不得把 M4、M5、旧里程碑或旧分支
写入结论**。
