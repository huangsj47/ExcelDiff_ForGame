# 配表体系与生效语义

本文件提供配表体系和生效语义，具体字段与入口需对齐冻结代码。平台只读分析，不执行写表、安装或导表动作。

## 1. 四种体系

| 体系 | 识别线索 | 取证要点 |
|---|---|---|
| 老Excel | A3字面量TYPE，5行表头含字段/类型/默认值/端侧 | 看A1身份、TYPE/DEFAULT/EXPORT与导出实现；字段type不等于表头TYPE |
| EditorCfgTool新表 | 常位于EditorCfgTool/excel，首行中文组件、4行表头 | 字段来自程序结构/组件，新增列不代表已导出和消费 |
| Web编辑器配置 | webconfig等JSON与行为树/地宫输出 | 区分权威输入和烘焙直出Lua，无源Excel不自动等于漏交 |
| 自定义表 | A1=SKIP，B列起中文列名，通常1行表头，可与老表同在config | 表名/类型/默认值/端侧来自CustomTableExport/def_files及规则，不套5行表头 |

奖励模式、随机奖励池、14外观采用自定义管线，具体身份仍以冻结表头和定义为准，不把旧“两文件三表”统计当固定全集。**SKIP这里不代表整表废弃**；A1判导出表名只适用对应管线。

## 2. 自定义奖励与外观

中文列名与定义配对，新列可能被忽略，改列名可能等同缺字段；先查定义和校验，不仅凭删列断言运行异常。自定义管线中A列为空才跳过行，非空“不要”不等于禁用；该规则仍要在冻结实现核对。

该管线入口为CustomTableExport/main.bat增量、main_all.bat全量；旧管线可能跳过这种表。改奖励字段要查定义、发奖消费和校验同步，不把一张表失败扩成所有表无法产出，除非找到共同入口依赖。

## 3. 物品和奖励

身份是 `(bigType,id)`，数量是第三个含义。取证入口为GoodsBigType2CfgName与BagCfgMod.getCfg(nBigType,nCfgId)，用冻结路由核实，不把旧8类当全集。

常见线索：1消耗、2普通回收物、3武器、4货币、9背包、12子弹、13虚拟、14外观。16等未收录类型先查类型表/路由，不猜名称或直接判不存在。逻辑架构页A1=CfgGoods不证明有一张总表_cfg.CfgGoods。

奖励最少串起：模式ID→玩法/条件/档位→物品名称用途→数量限制→实际到账。奖励行号不代表名次；不同资产无通用兑换比，不能要求新外观与旧货币必然等价。

## 4. 空值与两端

空不直接等于0或删除：老表看DEFAULT与生成访问方式，客户端可能有默认元表，服务端表示与兜底可能不同；自定义表看定义文件。显式0也要看主键和消费规则。

删列先查该端是否导出、代码仍否读取、默认/迁移/替代字段。只比较两端Lua字面不能证明运行期行为不一致。

## 5. 三种身份

Excel路径/工作表、生成表、运行期访问模块不同；一文件可多表，多文件可合表，有些产物无Excel源。用system-map/repo-layout定位，行数、空表、未接名单都须冻结重核。
