# G119 经济与数值基线（规则骨架）

> **用途**：给 `value_sanity` 一类的量级判断提供**基准的种类与出处**，并把「拿不到基准」的情形明确成一种写法。

> 本文件只告诉你**该去看哪张表**。设计目标值（产出速率、定价、各档区间）**在仓库里读不到** ——
> 读不到就按 §0 的「缺基准」写法写，**不要拿本文件的表述当数值依据**。

## 0. ⚠️ 先读这一节：本文件不含具体数字

**本文件的每一个数值都是空的（标 `待策划确认`）。** 因此：

- **不得**用本文件里的任何内容去断言某个具体数值「偏高 / 偏低 / 超档」。
- 凡涉及量级的判断，一律按 `version-diff-review` 的**「缺基准」写法**处理：
  `evidence` 里显式写出「**缺基准**：<为什么拿不到>」，`confidence` 只能给 `high`，**不许给 `very_high`**。
- 拿基准的正路仍然是**平台给的整表统计**（读同一张表时正文前会附每个数值列的最小/中位/P90/最大与文本列取值分布，按整表算、不受截断影响），以及同批次里这张表更早版本的分布对比。
- 本文件的价值在于告诉你**该去哪张表拿基准**，以及**哪些字段是「设计意图」而不是「实现细节」**（后者不能当异常报）。

**待填清单**（策划补数时按这几类填；明细与「哪些其实你自己能取」见 §9）：
`货币三币的兑换比 / 回收物各品质档位的价值区间 / 鉴定概率与保底规则 / 负重各段阈值 / 各难度的单局预期产出区间 / 道具买卖价差规则`

## 1. 货币体系

**货币分两套，互不干涉 —— 这是分析时最容易搞混的一点。**

| 层 | 货币 | 说明 | 状态 | 承载表 |
|---|---|---|---|---|
| **局外** | **点券** | 充值货币 | 在建（商业化整体在建） | `待策划确认` |
| **局外** | **金币** | 局外主货币：商店购买、维修、传送、配装等 | 在建 | 待确认 |
| **局外** | **兑换币** | 兑换用；口径为**三币全不清零** + **货币转换** | 在建 | 待确认 |
| **局内** | **梦币** | 局内货币：车厢商店购买、车厢传送消耗 | **已生效** | `CfgShop`（局内 NPC 商店，用 `nBigType + nCfgId` 指商品、`nPrice` 填局内价） |
| **物品化的货币** | 元宝 / 货币 / 角色币 / **家园币** | 以物品形式存在的货币，`bigType=4` | 部分已生效（家园币随家园在建） | `CfgGoods_currency`（`maxCount` 上限、`hasHistoryRecord` 是否记流水） |

「购买价格改了」**先问是哪一处**：**局内车厢商店**（`CfgShop`）/ **局外商店** / **商业化商城**（`CfgStoreGoods`，在建、程序未接）
—— 三处价格体系独立，改一处不影响另两处。

⚠️ **梦币与局外三币（点券/金币/兑换币）是否映射、梦币是否保留，暂无记录，不要自行等同、也不要自行推断。**
涉及梦币口径的改动，若 diff 里看不出二者关系，按 §0 的信息缺口写法处理。

## 2. 货币循环：产出与消耗口

```
产出口                                    消耗口
─────────────────────────              ─────────────────────────
局内搜刮回收物（Loot / GPE / 容器）  →   车厢商店（局内，梦币，开局前 20 秒）
  ↓ 车厢上交柜 / 带回局外                车厢传送（消耗局外金币）
局外鉴定（估值 / 激活图鉴）          →   局外维修（手枪 / 治疗针 / 除颤仪等有耐久道具）
局外出售（商店出售价）              →   局外商店购买
回收物图鉴（收藏 / 套装）               道具维修、配装
                                        〔在建〕局内代币消耗（抽奖 / 快捷撤离 / 简易补给）
                                        〔在建〕家园金币消耗口
```

**项目给出的换算口径（原话，供判断改动方向用）**：

> 单局产出 = 日产出效率 × (单局时长 / 每日预期总时长) × 难度系数

改动若触及其中任一项（`CfgDifficultyRegistration` 的单局最大时长与撤离金额、难度系数、产出速率），**要连带回归整个等式**，不能只看改的那一项。

**产消闭环的设计要求**：产出-消耗闭环 + 长线健康度指标检测。判断改动是否破坏闭环时，看的是**「同一件东西的买入价 / 卖出价 / 合成产出 / 兑换产出」的关系**，不是单个数字的大小。

## 6. 难度与结算的正相关（判断改动是否自洽的现成抓手）

| 表 | 为什么是抓手 |
|---|---|
| **`CfgDifficultyRegistration`（多难度注册表）** | **难度体系的唯一权威表**：按（难度组 `groupid`, 难度等级 `difficulty`）配**单局最大时长、坍塌阈值、撤离金额、刷怪周期方案、随机词缀池、天气词缀池**。另有 `地宫表`（难度下挂哪几个地宫布局）、`刷怪周期表`、`刷怪概率表`、`怪物模板表`、`怪物模板随机池`、`刷怪常量表`、`天气词缀库`、`天气随机池` 共 9 个 sheet |
| `CfgDungeonLootTemplate` | 按难度唯一 ID 给 22 种容器类型配掉落载体、数量区间、模态房比例与编辑倍率 → **决定该难度的 LOOT 预算与密度** |
| `CfgWithdrawSettlement` | 按难度配结算打分系数（胜/败、收获分乘数、怪物/精英加分、救援次数） |
| `CfgWithdrawEvaluate` / `CfgWithdrawEvaluateLevel` | 撤离评价档位阈值 / C·B·A 档图标与头衔 |
| `CfgWithdrawFailGoods` | 撤离失败保底发放 —— ⚠️ **只在测试包生效、只在服务器上用** |

**本项目的难度设计意图（判断改动的方向性依据）**：

- 普通难度 = 低密度、易理解的玩法；**高难增加挑战房 / GPE 组合 / 怪物干扰 / 路线选择压力，而不是「怪更多、更痛」**。
- 「保证越往深处探索奖励相对越丰厚」。
- 难度梯度参数：普通 / 高难的**怪物密度 · GPE 组合 · 路线选择压力**三项。

→ 所以「高难怪的属性变高」**不是**本项目表达难度提升的方式；看到这类改动，值得在报告里点出来（属设计意图层面的偏差，不是数值 bug）。

## 8. 本项目数值改动的高危模式（项目专属，作为 `value_sanity` 的补充清单）

| 模式 | 为什么在本项目特别危险 |
|---|---|
| **只改 `id` 不改 `nBigType`**（或反过来） | 物品表靠 `(nBigType, id)` 双键定位，`id` 在不同表之间重复 **39 处**且不报错 → **静默取到另一个物品**（见 `system-map.md` §2） |
| **`nDropId` 被清空 / 改错** | `CfgAppraise.nDropId` 不填**服务端发不出奖励** —— 客户端表现完全正常，玩家拿不到东西 |
| **买入价 / 卖出价关系反转** | 局内 NPC 商店价 `CfgShop.nPrice` 同时是 `BagCfgMod.getItemBuyPrice` 的兜底 → 卖价比买价高就是刷钱 |
| **只改一侧** | `CfgDifficultyRegistration` 的一个 sheet 改了、同难度挂在别的 sheet 上的参数没改 → 该难度自相矛盾（单局时长 / 坍塌阈值 / 撤离金额是一组） |
| **`CfgMonsterDrop` 掉落权重改动** | **只在服务器上用**，客户端看不到 → 出错时前端无任何异常表现 |
| **`CfgWeatherAffixPool` 的 `id` 不连续** | **id 必须从 1 连着编**，开局天气固定取池里第一条 → 断号会让首条天气固定错 |
| **`CfgWeatherAffix` 的类型/强度** | Excel 里是 **1-based**，且**只驱动客户端表现、不改玩法数值** → 改它不等于改玩法 |
| **`CfgConditionGroup` 条件改动** | 4408 行、被系统开放 / 邮件自动发放等统一引用；`CfgTaskConditionType` 还是**程序与策划的约定**：新增条件类型必须程序先写好处理函数，**否则游戏启动直接报错** |
| **常量表（`ConstCfg`）改动** | 全项目常量，10 个 sheet 合 1 张；历史上一次清理牵动全项目代码 → 改动必须与程序同批 |
| **`CfgTxtTemplate` 文案列** | 1287 行、`txtTemplateId` 被物品行引用，导表时自动填到武器/防具的 `name`/`desc` → 文案改动会大面积扩散 |

### 9.2 只能等策划补的（未补齐前必须走「缺基准」写法）

1. 三币兑换比与各币的**产出 / 消耗预算**
2. 回收物**品质档位名称**与各档**价值区间**（含「大金 / 大红」的正式定义）
3. 鉴定**概率表与保底规则**的目标形态（表 / 字段设计）
4. **负重分段曲线**的阈值与各段判定
5. 各难度的**单局预期产出**目标值与撤离金额设计值
6. 局内货币（梦币）与三币体系的**关系**（保留 / 映射 / 废除）
7. 道具**买卖价差**规则（是否允许套利、允许的比例上限）

> **这 7 条填完前，凡是依赖它们的判断都按 §0 写。** 但注意上一条：**分布类基准你自己就有**（整表统计 + 历史版本对比），
> 别把「我能取到的分布」也写成「缺基准」。
