# 玩法设计背景与QA场景

以下提供设计语义和回归方向，本轮实现以冻结配置和代码为准。

## 1. 主循环与Loot链

M5主循环：出生集结/购物→传送/野外→地宫探索→返程上交/撤离→结算。上交价值是主目标，死亡、超时、主动退出、观战留场结果不同；单局分钟数和金额读取当前难度，旧文档数值不当永久阈值。

链式交互整理：散点、容器、事件、机关串起“发现前置→操作→掉落/新通路/位移/高价值目标”。删产出时核实是不是某条链的奖励反馈，不只比一张表数量。

Loot点位使用预埋点+PCG的设计：固定容器/棺椁/事件按难度与全局上限，散点按面积密度配额再分房间。12米网格、150网格、15–20点等是**示例，不是当前目标**。

掉落体系包含建场静态与开箱动态掉落的设计、指定宝箱跨局保底、命中品质后清零；不证明所有宝箱都走保底，不能与鉴定保底混同。核实真实计数条件和权重。

验证：是否生成/打开→掉落可拾取→品质数量与设计→重试/重连不重复结算→撤离收益；无当前目标不能断言产出塌陷或一定无法撤离。

## 2. 吸灵器与战斗

M5的抓取设计包含可抓取标记、连接/拖拽/摔打、重量、多人协作；摔怪设计包含可吸取、反向摇杆积累进度、摔打与逃脱。这些是交互设计语义，不作为逐项已实现事实。

M6继续安排拖拽物体/定向摔打、玩法3C、技能/灵宠。串起瞄准→连接→动作→效果→奖励/脱离，覆盖打断、失能、目标失效、队友操作，不能只看按钮。

## 3. 道具与背包

道具栏与背包涉及装备/物品/吸灵器格、类型限制、负重、耐久、背包内被动、队友道具撤离后邮件返还。格子数、类型、返还规则核实当前实现。

类型/奖励变更检查进栏、耐久/弹药保留、负重、拾取替换、退出与撤离后的归属/到账。回收物不必然可出售，空价格需结合投放与计价。

## 4. 死亡与鉴定

旧死亡案关闭倒地，M6重新安排救援/爬行/复活；按本次模式和状态验证，不要求回退旧方案。提前退出与留场观战、个人与队伍结果分开核对。

早期鉴定设计包括局内与价值分档评语，M5基础体验为局外鉴定，M6仍迭代图鉴/鉴定。历史价格、评语阈值、保底设想不证明当前概率和价格。核实标识→消耗/替换→名称/价值→图鉴/检视，区别档位含义与文案。

## 5. 玩家反馈边界

玩法房的历史体验归纳是**待人工确认的定性背景，不是人数统计**。好评为互动/新鲜/收获/合作，差评为看不懂/平淡/回报不值/协作受阻；用于挑验证场景，不能算好评率或当作本轮配置事故证据。
