# G119 项目知识包

这是 **G119 项目专属**的知识包，供平台在做版本分析时挂载到项目上。

## 这里放什么

**项目事实**——「这个项目长什么样」。凡是换个项目就不成立的内容都属于这里：

- 玩法语义与局内流程
- 配置表的编号规则、命名规范、系统划分
- 项目的专有名词
- **导表产物的形态与前缀、哪些路径算关键路径**（这类事实平台要读，写在
  `references/project-facts.md` 的 frontmatter 里；平台的默认值对配表项目基本不适用）

## 这里不放什么

**评审方法与门槛**不放这里，它们在平台内置 skill（`skills/version-diff-review/`）里。
那是**项目无关**的：输出协议、检查维度、证据与置信度门槛、反误报规则、通用事故清单。
换一个项目接入平台时，那份 skill 原样可用。

两者的关系是：内置 skill 提供**方法与门槛**，本知识包提供**事实**。
事实以本知识包为准；**方法与门槛不可被本知识包覆盖**。

## 文件

| 文件 | 内容 |
|---|---|
| `references/gameplay-semantics.md` | 一局流程四阶段、核心系统、交互链的动作链与常见故障方向、职能路由、反过度归因护栏 |
| `references/config-table-spec.md` | 配置表 ID 规范（6 位、前两位为类型段）、命名规范、表结构约定、类型段与表划分、表与产物一起看的规矩 |
| `references/project-facts.md` | **平台要读**的那部分项目事实：导表产物的模块名前缀、关键路径的路径模式（frontmatter 是机器读的声明，正文写给人看） |

## 接入新项目时

在 `skills/projects/` 下新建一个以项目代号命名的目录，结构与本目录一致即可。
目录名与平台里项目的代号对应，用于自动挂载。
